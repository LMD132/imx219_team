# 形状识别 R3 负载诊断设计

日期：2026-10-01。状态：板子持有人已确认本设计稿；尚非实施或上板验证记录。

## 目标与边界

实板带图案时曾连续显示 `CNT000 OVFFFF F1 R3`，空白场景可显示 `F0 R0`。`R3` 是“槽位不足”与“输入帧已标坏”的位图；第二位并不等于 FIFO 已满，输入游程与帧边界同拍、待处理帧边界、重同步等也能把标记置坏。`OVFFFF` 是上电累计异常数饱和，无法继续用于比较当前负载。现有拥挤仿真只复现了 `R1`、`fifo_drops=0`，不足以推断实板的 `R3` 根因。

本轮目标是让调参界面分别显示槽位丢弃和 FIFO 满导致的游程丢弃，并在离线仿真中构造可重复的 `R3` 压力场景。诊断成功的判据是：两种事件能独立计数，旧状态字段语义不变，仿真能区分 `R1` 与含 `R2` 的故障；**不是**宣称识别已经修好。得到实板连续读数后，才选择针对瓶颈的 RTL 修复。此设计不改分类判据、阈值含义、HDMI 叠加、摄像头/DDR/引脚链路、`NB=8` 或 `FQ=24`。

只修改 `D:\FPGA_Project\imx219_shape` 的 `shape-detect` 候选版。最佳回退版 `imx219_notemp`、冻结版 `imx219_smooth` 与 `known_good/` 保持不动；不自动 JTAG 下载或擦写 Flash，也不把仿真结果当成板上因果证明。

## 方案选择

1. **推荐：扩展现有状态行。** 保留前 127 个可见字节（含现有 `CNT/OV/F/R`）逐字节不变，把原换行符后移，追加两个固定宽度十六进制字段。复用已有 CDC 握手和串口节拍；上位机仍按单行读取。代价是串口状态行从 128 增至 148 字节，字节索引须从 7 位增至 8 位。
2. 另发一条诊断行。原 128 字节状态行完全不动，但多一套消息时序与跨行配对规则；滑块连发和串口重连时更易混淆新旧采样。
3. 只做离线仿真计数。代码改动最小，却无法知道实板 `R3` 当时 FIFO 是否真的满，不能解决本轮诊断目的。

选择方案 1：现有串口读取循环按 LF 组行，不存在 128 字节的线缆协议上限；需要修改的是 RTL 内的索引宽度及测试期望。仍须通过综合和时序验证，不能预先假定资源足够。

## 事件语义与数据流

在 `rtl/algo/shp_detect.v` 增加两个 32 位无符号、模 `2^32` 累计计数器：

- `S`（slot drop）：每次现有 `no_slot_drop` 为真加一。这是“新游程没有匹配、空槽或可退休槽”的事件数，不是漏检目标数。
- `Q`（FIFO-full span）：每次 `span_end && f_full` 为真加一，无论同拍是否发生 VS。这只统计游程到达时队列已满；不把 `sync_lost` 后队列未满却拒收的游程、单纯的 `span_end && vs_edge`、或坏帧标记当成 FIFO 满。

两者在硬件复位时归零；形状识别关闭时保持、不增加；不随 GUI `R` 命令或阈值调整归零。`S/Q` 是长期累计模计数，`CNT/F/R` 仍描述最近一次提交帧，`OV` 仍是旧的 16 位饱和总异常数。它们可能来自不同帧，界面不得把同一行的 `S/Q` 差分解释成该 `F/R` 所指帧的精确事件数。

信号路径为 `shp_detect` → `alg_top` → 顶层现有 `alg_shape_diag_cdc` → `alg_cfg_telemetry` → UART → `tools/alg_tuner.py`。CDC 在一次 request/ack 事务内保持并拷贝完整诊断元组，由 32 位扩至 96 位；不直接逐位跨时钟读取计数器。状态行发送前锁存最近一次**已完成**的快照，握手在途仍沿用上一份完整数据。任一时钟域复位后样本无效，不能显示旧会话值。

状态行由当前 128 字节（含 LF）扩为 **148 字节（含 LF）**：原可见字节 `0..126` 原样保留；追加 ` Sxxxxxxxx Qxxxxxxxx`（各八位大写十六进制），唯一 LF 移到索引 147。`MSG_LEN` 保持能表示 148 的 8 位，`char_idx` 和 `msg_byte` 输入从 7 位扩到 8 位。周期和命令触发发送机制保持不变；原有 `R` 接收命令及滑块功能不变。

GUI 兼容旧 108、125、128 字节状态行和新 148 字节行。新字段缺失或收到 `F?`（尚无完整提交帧/有效诊断样本）时显示 `S/Q --`，即使串口发送了零也不伪造有效读数；收全新行且 `F` 有效时显示累计原值，仅在同一连接中、前后样本间隔不超过 5 秒、两计数器均未减小时显示各自的非负差值。断线、重连、收到 `F?`，或任一原值变小时清除差分基准，下一份样本重新开始比较；计数器回卷与未观察到的硬件复位无法可靠区分，因此这种情况下宁可暂不显示增量，也不报一个虚假的巨大增量。`OVFFFF` 继续提示饱和，但不影响 `S/Q` 的独立显示。

## 离线复现与解释边界

在现有 `tb_shp_clutter.v` 之外增加独立压力测试，保留现有 `R1` 回归。测试用完整 720p 节拍和有界的密集游程/并发小轮廓组合，分别覆盖：槽位耗尽但 FIFO 不满、FIFO 满而丢游程、两类压力同在且最近提交帧出现 `R3`。在测试台直接记录 `no_slot_drop`、`span_end && f_full`、坏标记入队/读取、`pending_edges` 与实际 `S/Q`，确认计数一拍一次、没有把 VS 碰撞误算为 FIFO 满。若构造出的帧因其他原因变为 `R7/RB`，先调整刺激并保留失败证据，不把非 `R3` 改写成成功。

串口 RTL 测试逐字节断言旧前缀、两个十六进制字段、148 字节总长和单个 LF；CDC 测试检查 96 位元组在异相时钟、更新中和任一侧复位时不撕裂、不带旧值；GUI 冒烟测试检查旧/新格式、半行、重连、计数器回卷或复位时暂停差分、以及无有效样本。随后运行形状、边缘链及界面回归，再执行 Efinity `map/interface/pnr/pgm` 四阶段并核对 setup/hold 与资源，尤其关注当前接近上限的 RAM。任何门禁失败均停止，不归档为可烧录候选。

如果压力测试复现 `R3`，它只证明代码路径可复现；实板必须观察连续多行 `S/Q/F/R`（并记录同一阈值与场景）才可归因。`ΔS>0, ΔQ>0` 支持两类负载同时发生；`ΔS>0, ΔQ=0` 而仍为 `R3`，转查 VS 同拍碰撞、待处理边界及重同步路径；两个增量均为 0 时先排除采样滞后，再查其他坏帧原因。后续优化识别吞吐或槽位策略另立设计与验证，不在本轮诊断中顺手更改。
