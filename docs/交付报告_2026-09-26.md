## 四、算法链（与 Python 一一对应）

```
摄像头 RGB
  → alg_gray        灰度 (77R+150G+29B)>>8        ← to_gray()
  → alg_median3     3×3 中值（19 比较器）          ← median3x3()      高阶①
  → alg_gauss5      5×5 整数高斯（核和 1010）      ← gaussian5x5()    高阶④
  → alg_sobel3      |Gx|+|Gy| + 方向量化          ← gradient()       基础③
  → alg_nms         非极大值抑制                   ← nms()            高阶④
  → alg_thresh      双阈值滞后 (58/21)             ← threshold_hysteresis()
  → alg_despeckle   去孤立点                       ← remove_isolated() 高阶④
  → alg_vdisp       显示对齐 + 4 种显示模式        ← split_view() / color_edge_overlay()
  → HDMI 输出
```

参数 = 仓库 `config.json` 定稿值（Canny、58/21、中值开、高斯关、去孤点开）。

## 五、最有价值的两个技术结论

### 1. `edge_pipeline.py` ≡ RTL（逐位）

两条独立证据链：

1. **溯源对拍**：`check_py_repo.py` 直接 `import` 仓库原文件（未改一行），与 RTL 金标准模型
   在真实照片 + 合成图上逐级比对，8 级全部 0 mismatch。
2. **RTL 对拍**：`check_chain.py` 用 iverilog 跑**真实 RTL**，与金标准模型逐像素比对，
   7 级 × 3 种模式全部 0 mismatch。

```
edge_pipeline.py  ≡  rtl_model.py  ≡  rtl/algo/*.v
        (溯源对拍 0 mismatch)   (全链路仿真 0 mismatch)
```

### 2. 显示对齐问题已解决（这是最容易翻车的地方）

算法主链 6 级窗口，累计让边缘值比彩色光栅**晚 7 行 7 列**出现，而它的 `(x,y)` 标签是
**源像素坐标**（比屏幕坐标小 7）。直接把边缘叠加到彩色上，实测 306 个显示像素里**错 80 个**。

解法（`alg_vdisp`，只动显示侧，算法一行不改）：彩色行缓存按"显示坐标"读、边缘行缓存按
"dsp 标签"写，两者自动归位 → 实测 **0 mismatch**。

额外做了抗错：本工程的显示光栅来自摄像头链路，**行周期不是综合期常量**，所以 `alg_vdisp`
会用"连续 3 次相同的行首间距"在运行期自动测出行周期。已用"把初值故意写错成 40"的方式验证过，
显示仍然 0 mismatch。

## 十、上板时建议按这个顺序看

1. 先确认能出图（可先用 `known_good/edge_detect_720p_verified.bit` 确认链路正常）。
2. 烧 `candidate_bitstreams/algo_canny_full_20260926_1954.bit`（**先重编译或核对哈希**，
   `outflow/` 切分支不跟着切）。
3. 看三件事：① 左右分屏的两半是否**同一完整视野**（左灰度 / 右边缘）；
   ② 人脸/棋盘轮廓是否连贯（Canny 应比纯 Sobel 干净）；③ 平坦白墙是否闪白点。
4. 若闪烁明显：**先锁 IMX219 曝光/增益（关 AE）**，这比继续抬阈值有效得多。
   再考虑上 `temporal_blend`。

JTAG 下载属易失性，断电后需重新下载；按 CRESET_N 可能重新加载 Flash 里的旧设计。
