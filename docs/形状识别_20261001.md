## 2. 算法怎么做的

### 2.1 数据来源

形状识别**不再单独取图**，直接吃边缘流水线的输出（`alg_despeckle` 的 `dsp_d`，
0 或 0xFF），所以和显示模式（Sobel / Canny / 左右分屏）无关：

```
dsp_vs, dsp_def, dsp_x[11:0], dsp_y[12:0], dsp_d[7:0]
```

### 2.2 流程（`rtl/algo/shp_detect.v`，帧末一次性结算）

1. **游程提取**：把每行连续的边缘像素压成一段 `(y, x0, x1)`，进 24 深 FIFO；
2. **blob 归并**：段的 bbox 与已有 blob 的 bbox 在水平方向有交叠（`GAPX=6`）且行距
   `<= GAPY=4` 就归并；同一行内多段取 min/max 合并成"整行跨度"；
3. **特征**（退休一个 blob 时算）：
   - `fill` = 每行跨度之和（不是边缘像素数！）
   - `area` = bbox 宽 × 高
   - `lsp`  = 最后一行的跨度（底边宽度）
   - `fill/area` 千分比与三个阈值比较（**无除法、无 DSP**：
     `fill*1000` 用移位 `<<10 - <<4 - <<3`，`area*fil_th` 用一个 11 拍移位加乘法器）
4. **分类**：

   | 判据 | 类别 | 颜色 |
   |---|---|---|
   | `r >= fil_th` | 2 = 矩形（填满 bbox） | 青 |
   | `600 <= r < fil_th` 且 bbox 近正方（0.7~1.43） | 1 = 圆 | 黄 |
   | `300 <= r < 600` 且 `2*lsp >= w`（底边占满） | 3 = 三角 | 品红 |
   | `300 <= r < 600` 且底边只中段 | 4 = 十字 | 绿 |

   （`r` = `fill*1000/area` 千分比；πR²/(2R)² = 785‰ 正好落在圆区间）
5. **筛选**：`min_size` 卡小噪点、`max_area%` 卡过大（比如整张纸）、最多 6 个框里
   按 `fill` 大小留前 `nbox` 个；
6. **帧末汇总**：`o_bx0/o_bx1/o_by0/o_by1/o_bcls/o_bval` 交给显示层。

### 2.3 为什么空心/实心都能识别（关键设计）

因为"每行跨度"取的是**该行最左边缘到最右边缘**（内外轮廓合并），
空心圆环和实心圆每行的跨度完全相同 → 填充率都 ≈ 785‰ → 都判圆。
方框和实心方块同理（≈1000‰ → 矩形）。这条性质是**结构性**的，
不依赖测试时选空心还是实心。

### 2.4 显示叠加（`rtl/algo/shp_overlay.v` + `shp_font.v`）

- 框线画在**源像素坐标**里（左右分屏模式自动做坐标还原：左半 `2x`、右半 `2x-1280`）；
- 标签是 32×16 点阵（2 个 16×16 汉字），摆在框上方 2px，顶格放不下时摆框下方；
- 字库 `shp_font.mem` 由 `tools/gen_font.py` 生成（圆 形 矩 三 角 十 字 未 知），
  占 1 块 BRAM；
- 优先级：下标小的框赢；颜色随类别。

## 3. 本轮修掉的两个真 bug（都是数据对得上的）

### 3.1 `b_sum` 被覆写 → 填充面积只剩最后一行

`shp_detect.v` blob 写回时原本是 `b_sum[i] <= mg_sum;`（覆盖），
而 `mg_sum` 一次只带"上一行跨度"，所以：

| 图形 | 修前 fill | 修后 fill | 正确值 |
|---|---|---|---|
| 空心圆环 165×165 | 26 | 21101 | ≈ πR² = 21101 ✓ |
| 方框 141×141 | 282 | 19881 | 141×141 = 19881 ✓ |

修前填充率全错 → 全部 `qual=0` 被丢掉（屏幕上什么都看不到）。
改成 `b_sum[i] <= b_sum[i] + mg_sum;` 累加。

### 3.2 乘法器握手时序洞 → 第 2/3 个乘积读到脏值

原实现用 `mul_run/mul_clr` + `mul_done=(m_cnt>=11)`：换状态那一拍 `m_cnt` 还是 11，
于是**立刻"完成"并读上一次的 `m_res`**。后果：`ret_area`/`r_a_th` 被污染
（仿真里看到 `a_th` 变成上一次的面积），`ok_area` 判失败 → 全部丢弃。

改成显式 **start 脉冲 / busy / done 脉冲**握手（`m_busy` + `mul_done_p`），
并把 `fill*1000` 从乘法器改成移位加法（`<<10 - <<4 - <<3`）。
现在只留 2 个乘积：`area = w*h`、`a_th = area*fil_th`。

| 现象 | 怎么办 |
|---|---|
| 完全看不到框/字 | 看调参台 `SHP` 是不是 1；`SZ` 调小（如 12）；`Z` 调大 |

## 8. 已知限制 / 下一步

1. 分类器只用 bbox + 填充率 + 底边宽度，**不区分空心/实心**（有意为之），
   也**不区分"正方形"和"长方形"**（都算矩形）。
2. 若纸上图形彼此靠得很近（水平间距 < 6px），`GAPX=6` 可能把它们并成一个 blob。
3. 旋转的十字/三角形仍可判（底边宽度判据对旋转 45° 的形状会退化），
   实际测试时尽量正对镜头。

### 9.3 用这份 PDF 直接测试时的注意点

PDF 每格外面有一圈**浅灰色圆角细框**（很淡）。若 Canny 阈值低到把灰框也
检出来，会额外冒出 4 个"矩形"框（灰框每行跨度=整格 → 填充率≈1000‰，
而且面积比图形大、会挤掉顶部排位）。处理办法任选：

1. 调 `T` / `L` / `H`，让灰框不出边（最推荐）；
2. `A`（最大面积%）调到 5~8：图形约 3%、整格灰框约 6~7%，可只留图形；
3. 打印时可裁掉/覆盖那圈灰框。
