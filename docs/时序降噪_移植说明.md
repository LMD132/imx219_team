# 时域降噪（TEMP）移植说明 —— GitHub Python 算法 → Verilog

本文记录**仓库算法 `temporal_blend()` 的 RTL 化**：它对应 `live_tune.py` 界面上那条
`TEMP` 滑条，是我们这条流水线里唯一"跨帧"的算子。

> 一句话结论：`TEMP` 用 **DDR 里的上一帧 bank** 做帧间加权平均，硬件上只多了一条
> DDR 读流 + 一个 512 深的 read FIFO + 一个纯组合的逐字节融合器；`TEMP=0` 时
> 输出与改动前**逐位相同**（走直通，不走公式）。

---

## 1. 算法来源（唯一权威，不许自行发挥）

`FPGA-Python/edge_pipeline.py:338`：

```python
def temporal_blend(prev, cur, alpha):
    if prev is None or alpha <= 0:
        return cur
    return np.clip(alpha * cur.astype(np.float32)
                   + (1 - alpha) * prev.astype(np.float32), 0, 255).astype(np.uint8)
```

`FPGA-Python/live_tune.py:166-168`（GUI 滑条 → `alpha`）：

```python
alpha = 1.0 - temp_val / 100.0 if temp_val > 0 else 0.0
gray_t = temporal_blend(prev_gray_n, gray_n, alpha)
```

调用顺序（`live_tune.py` 的链路）：

```
gray → TEMP(temporal_blend) → median → EPF → gauss5 → sobel → nms → thresh → isol
```

即 **TEMP 是灰度化之后的第一个算子**，作用在灰度帧上。

## 2. 定点化：TEMP → alpha（Q8）

`alpha = 1 - TEMP/100` 用 Q8（×256）定点：

```
alpha_q8 = round((100 - TEMP) * 256 / 100)
out      = (alpha_q8 * cur + (256 - alpha_q8) * prev) >> 8      // 截断，不是四舍五入
```

| TEMP | 0 | 10 | 25 | 50 | 75 | 90 |
| --- | --- | --- | --- | --- | --- | --- |
| alpha_q8 | 0 | 230 | 192 | 128 | 64 | 26 |
| 直读含义 | 关 | 当前帧 0.90 | 当前帧 0.75 | 各半 | 当前帧 0.25 | 当前帧 0.10 |

要点：

- **`TEMP=0` 必须走直通**（`out = cur`），不能套公式 —— 套公式会变成"纯上一帧"。
  RTL 上是 `(alpha_q8 == 0) ? cur : blend`，对应 Python 的 `if alpha <= 0: return cur`。
- `>> 8` 是**截断**（`np.uint8` 的语义），不是四舍五入，最大差 1 LSB 是定点化代价。
- 滑条量程 **0..90**（用户指定）：`90` 已经是 alpha≈0.1，再大在 8bit 灰度上几乎只剩拖影。
  超过 90 的输入在 `alg_cfg_uart.v` 里夹到 90。
- 开机默认 **TEMP=0**（关）。`config.json` 里写的是 `temp=50`，要在板上复现那个定稿值，
  把界面滑条拖到 **50** 即可（那是唯一一处"默认值不等于 config.json"的地方，特意如此，
  好让"不碰滑条"时的画面与上一版**逐位一致**，方便 A/B 对比）。

## 3. RTL 落点

```
IMX219 → MIPI → frame_buffer(checker0)
   写入:  ·  → DDR3 bank wr_bank
   读出:  ─┬─ 当前帧 bank(rd_bank)     ─→ u_rd_fifo      (1024×128b) ─┐
           └─ 上一帧 bank(rd_bank-1)   ─→ u_rd_fifo_prev ( 512×128b) ─┤
                                                                      ├→ alg_blend_bytes(NBYTE=16)
                                                                      │      (纯组合, 逐字节)
                                                                      └→ vid_par2ser → o_fifo → 显示
```

| 文件 | 角色 |
| --- | --- |
| `rtl/frame_buffer_V4/ddr_rd_buffer.v` | 一个地址发生器**交替**发两条流的 AXI 突发；两条流各进一个 FIFO |
| `rtl/algo/alg_blend_bytes.v` | `temporal_blend` 的整字并行版（128bit = 16 个 8bit 像素一次算完） |
| `rtl/algo/alg_blend.v` | 同一算子的逐字节版（`alg_top` 里的备用挂点，时序/单测与前者同源同判据） |
| `rtl/alg_temp_sync.v` | TEMP 的跨时钟域（`CLK_25M` → `vid_clk_dvi2`） |
| `rtl/frame_buffer_V4/bank_switch.v` | 四缓冲轮换，输出 `rd_start_addr_prev`（= 上一帧 bank 基址） |

### 3.1 偏离登记：融合发生在 **Bayer 域**，不是参考代码的灰度域

DDR 里存的是 8bit Bayer，板上只有一条 debayer 通路（`debayer_top_2to1`），要在灰度域
融合就得再开一条 debayer + 灰度化通路（≈10 块 Memory Block，而全设计 Memory 已经
81% 满）。所以把融合提前到 DDR 读出侧、debayer 之前。

**为什么等价**：debayer 和灰度化都是**线性加权**（`gray = (77R+150G+29B)>>8`，
`R/G/B` 是 Bayer 邻居的线性组合）。线性算子与"帧间线性插值"可交换，所以
"先融合再 debayer"与"先 debayer 再融合"只在**内部截位**上有差别（≤1 LSB），
数学上同一件事。这也是 ISP 里时域降噪（3DNR）的常规位置。

> 登记位置：`docs/ALGO_RTL.md` §4 与 §11。

### 3.2 为什么是 FIR（读上一帧 DDR）而不是 IIR（递归帧缓冲）

`temporal_blend(prev, cur, alpha)` 里的 `prev` 在 Python 是"上一帧的**原始**灰度"，
不是"上一帧的融合输出"。所以：

- **FIR**：`prev` 直接从 DDR 的上一帧 bank 读 → 与 Python 逐位对齐，
  不需要额外的递归缓冲，也不会把误差累积下去；
- IIR（`prev = 自己上一拍的输出`）：省一条 DDR 读流，但**语义不是参考算法**，
  而且静止画面会有无限累积的"渐入"效果。

结论：采用 FIR。实测（离线回放模型，σ=16 噪声）闪烁指标
**TEMP=0 时 117.0 → TEMP=30 时 34.2**，两种做法收益相当，所以选语义正确的那种。

## 4. 双基址交替突发：一个地址发生器怎么读两个 bank

### 4.1 四缓冲不变量（`bank_switch.v`，FB_NUM=4）

```
wr_bank      = rd_bank + 1    写侧比正在显示的那一帧新一帧
rd_bank - 1  = 上一帧          读侧还要读它, 写侧碰不得
clean_bank   = 刚写满的那一帧   等 clean_en, 读侧一滚它就变成新的 rd_bank
```

任何时刻 `{wr_bank, rd_bank, rd_bank-1}` 是 3 个互不相同的 bank，
所以"读当前帧 + 读上一帧 + 写新帧"可以同时进行。4 个 bank 是**必要条件**：
3 个 bank 时"正在显示 / 上一帧 / 正在写"三个角色排不下，上一帧必被写端踩掉。

`FRAME_LEN` 向上取整到 4096（`FRAME_LEN_RAW = 640*720*16/8 + 0x200` → 925696 字节），
于是各 bank 基址**低 12 位相同** —— 这是"一个地址发生器服务两条流"的前提：
两条流的 4K 突发切分（first / mid / last 长度）完全一样，差的只是基址。

### 4.2 突发序列

一帧里发的顺序是：

```
当前帧[0] → 上一帧[0] → 当前帧[1] → 上一帧[1] → ... → 当前帧[N-1] → 上一帧[N-1]
```

总发数 `2N` 是偶数，所以**最后一发一定是"上一帧"那条**。两条流各自的突发长度序列
都是 `first, BURST_LEN×(N-2), last`（与原单流版完全一致），因此第 k 个字在两条
FIFO 里指向**同一个像素位置**，下游同拍排空就天然配成对。

### 4.3 三处必须小心的地方（都是踩过的坑）

1. **`arlen` 必须是组合的**。原版用"每发 `rd_addr_en` 就把**下一发**的长度预置进
   寄存器"，那套只在单流时成立：交替下第 k 发与第 k+1 发属于**不同 bank**，
   寄存器的值会串到另一条流上（第 0 发碰巧还是对的，因为两条流的第 0 发都是 `first`，
   从第 2 发开始就错了）。现在 `arlen = sel_arlen`（由 `sel_seg` 组合给出）。
2. **数据侧要另用一个"这一发是谁"的标签 `ddr_stream_r`**。`rd_prev_sel` 在 AR 握手
   那一拍就翻到下一发，而这一发的数据要过好几拍才回来 —— 直接用 `rd_prev_sel` 决定
   写哪个 FIFO，会把整发数据写进错的 FIFO。`ddr_stream_r` 在 AR 握手时抄下旧值，
   到下一次 AR 才变；状态机是"发完一发、收完 `rlast` 才发下一发"的串行结构，
   最后一次 `ddr_rd_valid` 比下一次 AR 早 ≥2 拍，所以标签对每个数据字节都成立。
3. **`ddr_read_stop` 必须加 `rd_prev_sel`**。`sel_last` 对两条流**都会**成立
   （各自的 `seg` 都会走到 `burst_num-1`）；一帧的最后一发是"上一帧"那条，
   若不限定，会在倒数第二发（当前帧最后一发）就把状态机停掉，上一帧少 128 个字，
   整帧错位。

### 4.4 为什么恒定交替（不给 TEMP=0 做开关）

读侧在 `axi_clk` 域、排空/融合侧在 `o_clk`(=vid_clk_dvi2) 域。若两边各自判断
"这一帧读不读上一帧"，滑条一动的瞬间两边判断会错开一帧：排空侧要等上一帧 FIFO 的
数据而读侧没发 → 双 FIFO 排空把整帧卡死。恒定交替在结构上没有这个风险。

代价只是 DDR 读流量翻倍：一帧 ≈900 个 128 拍突发，按显示侧消耗速度算
（1280×720×2 字节 ÷ 16.7 ms ≈ 6.9 MB/s 量级）远小于 DDR3-800 ×16 的 1.6 GB/s；
`TEMP=0` 时画面靠 `alg_blend_bytes` 的 `alpha==0` 直通，逐位等于单流版本。

### 4.5 排空侧的配对

`vid_par2ser` 的 `rd_fifo_rdempty` 喂的是 **`rd_fifo_rdempty | rd_fifo_rdempty_prev`**：
两条都非空才排空。只排一条会让两个 FIFO 的读指针错位，配到的就不是同一像素位置。
`DC_FIFO` 是 Normal 模式（RdEn 后**一拍** `RdData` 才有效），两路同拍 `RdEn`、
同拍出数据，所以融合器可以是**纯组合**、不吃延迟。

## 5. 资源与时序（2026-09-28 实测，非估算）

预测值先写在括号里，实测值取自 `outflow/ti60f225_oob.hier_util.rpt` 与
`outflow/ti60f225_oob.timing.rpt`（同一份代码的 `map/interface/pnr/pgm` 全 PASS）：

| 项 | 预测 | 实测 |
| --- | --- | --- |
| Memory Blocks | +7（上一帧 FIFO 512×128b ≈ 64 Kbit / 10 Kbit 一块） | **224 → 231 / 256**（+7，与预测一致；其中 `u_rd_fifo_prev` 独占 7 块） |
| DSP Blocks | 32 个 8×8 乘法映射到 DSP | **45 → 71 / 160**（+26；128bit = 16 字节 ×2 个乘法器） |
| XLRs | +几百 | **28436 → 29425 / 60800**（+989；`u_alg_blend_bytes` 412、`u_rd_fifo_prev` 196） |
| 全设计 setup / hold | 不为负 | **全正**：最小 setup `+0.304 ns`（`tx_cal_clk`，DDR PHY 既有路径）、最小 hold `+0.026 ns`（`core_clk`） |
| 融合所在的 `vid_clk_dvi2` | — | setup `+17.676 ns`（周期 26.936 ns）、hold `+0.042 ns` |
| `hdmi_tx_slow_clk` | 不低于基线 | setup `+4.853 ns`（基线 +4.524 ns，反而更松） |

其他相关项：

- 32 个 8×8 乘法是**纯组合**，落在 37.125 MHz 的 `vid_clk_dvi2` 域
  （周期 26.936 ns），实测该域 setup slack 17.7 ns，余量充足。
- 交替读的关键路径 `sel_seg → sel_first/sel_last → sel_arlen → nx_ddr_addr`
  在 `axi_clk` 域（输入全是寄存器，25bit 比较 + 8bit mux + 一个加法器）；
  顶层 `axi_clk` = `core_clk`（100 MHz），该域 setup slack `+2.653 ns`。
- Memory Blocks 现在 **231/256 = 90.2%**，继续加帧级功能前必须先处理这块
  （见 `docs/ALGO_RTL.md` §10 的出口清单）。

## 6. 已知取舍（必须如实说明）

- **运动拖影**：帧间平均的固有代价，`TEMP` 越大越明显（参考算法同样如此，
  `live_tune.py` 的注释也是这么写的）。静止目标变稳，运动目标发虚 —— 这是用户
  在滑条上自己权衡的量。
- 显示侧一路是 **RGB565**（`alg_vdisp` 输出 16bit），所以链路上的 1 LSB 差异在屏幕上
  可能看不出来。
- 参考 Python 的 `temporal_blend` 只在"上一帧存在"时才融合；板上第一帧（或复位后
  `bank_switch` 还没转起来时）上一帧 bank 里是 DDR 的旧内容 —— 与 Python 的
  `prev is None` 无法逐位等价，属于上电瞬态。
