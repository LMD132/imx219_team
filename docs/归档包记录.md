# 归档包记录

每打一个留档/交付压缩包就在这里记一行，便于回答"交给别人的是哪一份、对应哪个提交"。

`.zip` 本体放在**仓库外**的 `D:\FPGA_Project\_archives\`：33.8 MB 的二进制放进 git 会让
仓库体积翻倍，而包又是从仓库派生出来的，没有必要双向保存。同一份索引也写在
`D:\FPGA_Project\_archives\ARCHIVE_INDEX.txt`。

## 打包命令

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_archive.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_archive.ps1 -Label 交付前
powershell -NoProfile -ExecutionPolicy Bypass -File tools\make_archive.ps1 -SourceOnly   # 排除构建产物
```

包名格式：`<目录>_<分支>_<提交>[_标签]_<打包时间>.zip`，所以看一眼文件名就知道是哪一版。

## 包内为什么不含 .git

原工作区的 `.git` 只是一个 64 字节文本文件，内容是指向本机绝对路径的指针，换台机器没有意义，
所以没有放进去。真正的历史在 `_archive_info/GIT_HISTORY.git_all.bundle`，含全部分支：

```powershell
git clone _archive_info\GIT_HISTORY.git_all.bundle my_repo
git -C my_repo branch -a
```

只要代码、不要 git 历史，直接解压即可。注意 `git clone` 会把带 `text` 属性的源文件
（`*.v` 等）改写成 CRLF，而解压出来的那份是逐字节原样。

## 校验

```powershell
Get-FileHash -Algorithm SHA256 <包名>.zip     # 与上表比对
# 解压后，在包根目录逐个文件比对：
Get-FileHash -Algorithm SHA256 rtl\algo\alg_top.v   # 与 _archive_info\SHA256SUMS.txt 比对
git bundle verify _archive_info\GIT_HISTORY.git_all.bundle
```

## 踩过的坑：zip 里的中文文件名

仓库有 4 个中文名文件（`docs/上板记录_2026-09-26.md`、`docs/交付报告_2026-09-26.md`、
`docs/运行期调参.md`、`sim/algo/model/ref/FPGA-Python-main/RTL交接文档.md`）。

Windows 自带 `tar.exe`（bsdtar 3.8.8）**默认把非 ASCII 条目名按 ANSI 代码页写入，且不设
UTF-8 标志位**。在本机解压正常，因为本机也是 GBK；发给别人或换非中文系统就全是乱码。
实测同一个文件名：

| 做法 | 头部标志 | 名字字节 | 结果 |
| --- | --- | --- | --- |
| `tar -a -cf` | `0x0008` | `C9 CF B0 E5 ...`（GBK） | 换机器乱码 |
| `tar --options zip:hdrcharset=UTF-8 -a -cf` | `0x0808` | `E4 B8 8A E6 9D BF ...`（UTF-8） | 正确 |

脚本已改用第二种，并且打完包后会**重新打开自己的 zip 自检**：条目名出现替换字符就报错退出，
同时核对每个待打包文件都有对应条目。所以坏包不会被打出来蒙混过关。
