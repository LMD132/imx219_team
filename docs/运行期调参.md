# 运行期调参通道（UART + PC 界面）

**一句话**：插上 USB 串口线（COM5），运行 `python tools/alg_tuner.py`，
拖动滑块 → 屏幕**立即**变化，**不需要重新编译，也不需要重新烧录**。

---

## 1. 为什么现在可以实时调

`rtl/algo/alg_top.v` 的每一个可调参数本来就是**运行期输入端口**
（`cfg_mode / cfg_t / cfg_lo / cfg_hi / cfg_median_en / cfg_gauss_en /
cfg_isol_en / cfg_disp_mode / cfg_ov_color`），不是综合期常量。

以前"调参 = 改 Verilog → 编译约 2 分钟 → 烧录约 1 分钟"，原因只有两个：
顶层把这些端口**接成了常量**，而且板上没有参数输入通道。二者都在
2026-09-26 补上了：

```
PC (tools/alg_tuner.py)  --USB-->  FT4232H ch.C  -->  板 UART (GPIOR_28 / GPIOL_02)
                                                             |
                                                       alg_cfg_uart.v   (CLK_25M 域的寄存器组)
                                                             |
                                                       alg_cfg_sync.v   (跨到 HDMI 像素时钟域)
                                                             |
                                                       alg_top 的 cfg_* 端口  -->  画面
```

**算法 RTL（`rtl/algo/*.v`）一行未改。** 本次只增加"参数从哪里来"的通路，
参数名、位宽、默认值与之前写死的常量**逐一对应**；不接串口时行为与旧版一致。

## 2. 硬件连接

| 信号 | 板引脚 | 方向 | 电平 |
| --- | --- | --- | --- |
| `o_uart_txd` | `GPIOR_28`（R14） | 板 → PC | 3.3 V LVCMOS |
| `i_uart_rxd` | `GPIOL_02`（R4） | PC → 板 | 3.3 V LVCMOS，弱上拉 |

- 主机端口：**COM5** = FT4232H channel C。COM6 是 channel D，**不接 FPGA**
  （它是很好的反证：用 COM6 收发必然无回读）。
- 波特率 **115200 8N1**，参考时钟 `CLK_25M`，分频系数 217。
- 这条 UART 通路不是新设计的：引脚、波特率、端口号取自同一块板上**已验证**的
  姊妹工程 `D:\FPGA_Project\imx219_team`（分支 `uart-bringup`），
  `rtl/uart_rx.v`、`rtl/uart_tx.v` 是**逐字复制**，未改一行。

## 3. 命令协议（`rtl/alg_cfg_uart.v`）

一行一条（或一行多条），以 LF 或 CR 结束：

| 命令 | 参数 | 取值范围 | 默认值 |
| --- | --- | --- | --- |
| `M<n>` | `cfg_mode` | 0=单阈值 Sobel，1=双阈值 Sobel，2=Canny（>2 截到 2） | 2 |
| `T<n>` | `cfg_t` 阈值（仅 SOBEL 单阈值档用） | 0..2047（该档量程 0..2040） | 24 |
| `L<n>` | `cfg_lo` 滞后低阈值 | **0..255**（CANNY 档） | 21 |
| `H<n>` | `cfg_hi` 滞后高阈值 | **0..255**（CANNY 档） | 58 |
| `N<n>` | `cfg_median_en` 中值使能 | 0/1 | 1 |
| `G<n>` | `cfg_gauss_en` 5×5 高斯使能 | 0/1 | 0 |
| `I<n>` | `cfg_isol_en` 去孤点使能 | 0/1 | 1 |
| `D<n>` | `cfg_disp_mode` 显示模式 | 0..3 | 0 |
| `C<n>` | `cfg_ov_color` 彩色叠加 | 0/1 | 1 |
| `R` | 全部恢复开机默认值 | — | — |

分隔符宽松：`T24`、`T=24`、`T 24` 等价；字母大小写均可。
数值是**饱和累加**，所以 `T9999` 得到 2047 而不是回绕。
一行可以写多条：`T7 L8 H9`。无法识别的键（如 `Q`）被忽略，不影响其它命令。

### 3.0 阈值的量纲：为什么 `L` / `H` 是 0..255，而 `T` 是 0..2047

**这两个范围不一样，是因为它们比较的对象不一样。** 见 `rtl/algo/alg_top.v`：

```verilog
wire [10:0] thr_mag = (cfg_mode_d == 2'd2) ? {3'b0, nms_d} : sob4_mag;
```

| 显示/算法档 | 阈值级比较的对象 | 位宽 | `T` | `L` / `H` |
| --- | --- | --- | --- | --- |
| mode 2 CANNY（当前） | NMS 输出 `nms_d`，`clip(m,0,255)` | 8 bit | 不用 | **0..255** |
| mode 1 SOBEL 双阈值 | Sobel 全量程 `\|Gx\|+\|Gy\|` | 11 bit | 不用 | 0..2040 |
| mode 0 SOBEL 单阈值 | Sobel 全量程 `\|Gx\|+\|Gy\|` | 11 bit | 0..2040 | 不用 |

所以：

- **`L` / `H` 在 CANNY 档的真实量纲就是 0..255**（NMS 输出已经被 `clip(m,0,255)` 压到 8bit），
  GUI 滑块因此按 0..255 给。
- **`T` 只在 SOBEL 单阈值档生效**，那一档比较的是 11bit 全量程梯度（0..2040），
  所以 `T` 的滑块仍保留 0..2047，**不要跟着改成 255**，否则那一档永远只能取到很低的门限。
- **换成 mode 1（SOBEL 双阈值）时，滑块上限 255 不够用**：那一档的梯度能到 2040。
  串口命令不受影响（RTL 仍接受 0..2047），只是滑块拖不到。要那一档用滑块的完整量程，
  说一声我把上限定成随档位自动切换。

协议层（`alg_cfg_uart.v`）对 `L`/`H` 的饱和上限仍是 2047 —— 因为矢量对同一份 RTL 的
两种档位共用，限制在 2047 对两档都安全。GUI 收窄到 255 纯粹是为了**拖动精度**：
2047 档位摊在约 450 px 的滑块上是每像素约 4.5，很难停在 27、31 这种值；
0..255 则是每像素约 0.57，可以逐 1 调。

### 3.1 状态回读（遥测）

板子每 **500 ms** 主动发一行状态，收到命令后**立即**再补发一行：

```
M2 T0024 LO0021 HI0058 MED1 GAU0 ISO1 DSP0 OVC1\r\n
```

固定 49 字节。这就是 GUI 右边"板端"那一列的来源 —— 用它来自证链路真的通了，
而不是只看 PC 单方面发出去了什么。

## 4. PC 界面：`tools/alg_tuner.py`

依赖：Python 3 + `pyserial`（tkinter 随 Python 自带）。

```bat
cd /d D:\FPGA_Project\imx219_pyrtl
python tools\alg_tuner.py --port COM5 --connect
```

`--port` / `--connect` 可以省：不带参数时下拉框会**自动挑第一个 FTDI/USB Serial 口**，
但要手动点"连接"。**本机 COM3/COM4/COM5/COM6 都是 FT4232H 的通道，只有 COM5 接 FPGA**，
所以建议显式写 `--port COM5`，省得选中 COM6 之后对着"无回读"发呆。

- 顶部选串口（下拉框自动优先列 USB Serial / FTDI 设备），点"连接"。
- **每个参数一行**：中文名 + 滑块 + 本机值 + 「板端」回读值 + 单位/说明。
- 本机值与板端值一致 → **绿色**；不一致 → **红色**，状态栏列出差异。
- 拖动节流 60 ms，避免刷爆串口。
- 「全部下发」把当前所有滑块值重发一遍；「恢复默认 (R)」等价于 `R`；有日志区显示 TX/RX。
- 状态栏超过 1.5 s 没有回读会提示："串口选错了？板子没跑这个位流？"

前一层失败就不要往下走，否则会把主机侧 bug 误判成板子问题。

## 6. 本检查点抓到的两个真 bug（记录以便复查）

1. `alg_cfg_uart.v` 的饱和累加器位宽不足：原来 `reg [12:0]` 只有 13 位，
   而 `2047*10+9 = 20479` 需要 15 位，导致比较 `> 4095` 永不成立，
   `T9999` 得到 1807 而非 2047。改为 `reg [15:0]` 后正确。
   **教训：饱和逻辑的中间变量必须能容纳未饱和的原始值。**
2. `alg_tuner.py` 用了 `ttk.Label.set()`（`ttk.Label` 不是 `StringVar`），
   一点滑块就 `AttributeError`。改为 `configure(text=...)`。
   **这个 bug 只有真的拖动滑块才会暴露，静态语法检查看不出来。**

## 8. 界面是调试工具，不是演示内容

赛题"实时阈值调节"的字面要求是**板上按键 ± 含消抖**。当前实现是
**PC 串口**运行期可调，属于功能等价但形式不同：评审若严格按"按键"扣分，
缺口仍然存在（顶层无按键输入、未写消抖）。见 `CONTEST_CHECKLIST.md` 高阶②。

本界面另外的定位：**取证工具**。它可以一边看屏幕一边改参数，
是拿到 F 级"肉眼画面确认"证据最省事的方式（`docs/上板记录_2026-09-26.md` §5 观察清单）。
