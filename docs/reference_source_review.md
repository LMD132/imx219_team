# 参考源码逐份阅读结论（2026-09-25）

用户给的目录里有一份 **`【源码】基于易灵思FPGA的实时图像边缘检测系统.zip`（41 MB）**，
就是上一次分析的那段 B 站参照视频的工程源码。已解到 `work/ref_src/`（work 被 gitignore）。

## 1. 参照工程的真面目：`sobel/src/Sobeledge_8d/hdl/`

数据流（`example_top.v`）：

```
OV5640(1280x720) -> cmos_top -> vip_rgb2gray_proc -> Sobeledge_8d_proc -> DDR -> lcd_driver -> rgb2dvi -> HDMI
```

**没有中值滤波，没有形态学，没有任何去碎斑**。整个"干净"的效果只来自 `Sobeledge_proc.v` 里的两块：

```verilog
// 4 个方向算子各算一次，取最大
G0   = |(p11+2p12+p13) - (p31+2p32+p33)|;     // 0°
G45  = |(p23+2p33+p32) - (p12+2p11+p21)|;     // 45°
G90  = |(p13+2p23+p33) - (p11+2p21+p31)|;     // 90°
G135 = |(p12+2p13+p23) - (p21+2p31+p32)|;     // 135°
Gmax = max(G0,G45,G90,G135);

// 三个模式开关：原图 / 边缘强度 / 二值
source_data = edge_en ? (bin_en ? ((Gmax >= center) ? 8'hff : 8'h00)   // 阈值 = 中心像素自己
                                 : ((Gmax > 510) ? 8'hff : Gmax[8:1])) // 强度/2，饱和
                      : center;
```

关键点：**二值化阈值不是常数，也不是"中心灰度的某个比例"，而是中心像素灰度本身**。
原作者注释说是"根据论文中的算法，输入数据是中值滤波后的图像，所以只需要让 Gmax 和中心点比较"。

## 2. 把这条规则搬到我们自己的实拍帧上（`tools/proto_edge_modes.py`）

输入：采集卡抓的整帧，取**左半灰度**当灰度源（和板子上的 Sobel 输入是同一个信号）。

### 2.1 `Gmax >= center` 单独用会在暗区整片变白（不要照抄）

亮场景帧（`work/capture/ab_e2_t24/frame_00.png`，灰度 mean=57.2）：

| 模式 | lit% | 连通域 | 碎斑≤3px | 碎斑像素% |
|---|---|---|---|---|
| A 我们：`\|Gx\|+\|Gy\|`, thr=max(24, c>>1) | 37.39 | 5426 | 3895 | 3.46 |
| A2 同上算子, thr=max(24, c) | 20.08 | 5636 | 4098 | 6.46 |
| B 参照算子 max4, thr=max(24, c>>1) | 29.92 | 5500 | 3870 | 4.43 |
| **C 参照规则 max4, thr=c（无下限）** | 30.83 | 4339 | 3011 | 3.19 |
| D C + 下限 + 去碎斑 | 25.75 | 1831 | 442 | 0.69 |
| E 当前实现 + 去碎斑 | 33.03 | 2007 | 669 | 0.82 |

拼图：`work/analysis/proto/bright/proto_compare.png`（上排 A/A2/B，下排 C/D/灰度源）。

**C 面板左上角出现一大片纯白**——那片在灰度里是接近 0 的死黑区，`center≈0` 于是
`Gmax >= 0` 恒真，整片点亮。这就是照抄参照规则的后果。

暗场景帧（`work/capture/flick_ab/frame_00.png`，灰度 mean=**1.0**）：

| 模式 | lit% | 连通域 | 碎斑≤3px |
|---|---|---|---|
| C 参照原始规则 | **85.29** | 390 | 200 |
| B max4 + max(16, c>>1) | 0.25 | 43 | 28 |
| A 我们 `\|Gx\|+\|Gy\|` + max(16, c>>1) | 0.46 | 150 | 100 |
| D = B + 去碎斑 | 0.23 | 13 | **2** |

场景越暗，`Gmax >= center` 越容易整屏变白（85.29%）。

### 2.2 4 方向算子 vs 我们的 `|Gx|+|Gy|`：观感差别很小

A / A2 / B / C 四张图肉眼几乎一样（都被输入里的竖条纹和噪点主导）。
**结论：不值得为此改 RTL、花时序余量。** 真正把碎斑打掉的是**去碎斑**（D、E 两行：
tiny 3011→442、连通域 4339→1831），也就是我们 `edge_overlay_720p.v` 里已经有的那一级。

### 2.3 我们和参照的根本差别：输入灰度

参照工程 IMX/OV 传感器 + 明亮办公室，灰度本身干净，所以"什么都不做"就很漂亮。
我们的输入灰度现在有两个问题（见 §3）：太暗、以及亮场景下有竖条纹（已修但仍需留意）。

## 3. 当前现场实测（2026-09-25，`tools/comb_phase.py`）

```
frames 114 in 5 s, grey half 640 x 720
grey half mean 10.52            <- 最近一次亮场景的同类测量是 55~60
column term  A_x  = +0.0027     <- 条纹已修（修复前 +0.2199）
row term     A_y  = +0.0004
```

**结论：条纹问题已经解决，但场景/曝光太暗（均值 10.5）**。后果：
`center >> shift ≈ 0` → 自适应项失效 → 退化成固定 floor=16 → 暗区全是噪点、
暗物体轮廓更少。**这解释了我们为什么非要去碎斑，而参照工程不需要。**

## 5. 建议的顺序（对上参照效果）

1. **先把输入亮度/曝光拉起来**（开灯 / 增益 / 前端灰度拉伸或直方图均衡）。这是参照工程"干净"的前提；
   不解决它，阈值怎么调都是在噪点里挑。
2. 保留并微调**去碎斑**（已有），它贡献最大。
3. 修 bbox 的"撑满屏"（行/列投影，而不是 min/max 单点）。
4. **4 方向 Sobel 不做**（收益小）；参照的 `Gmax>=center` 不照抄（暗区会白屏）。

## 6. 上板实测：把自适应权重 `S` 调成 0 ≈ 参照工程的规则（2026-09-25 白天，实验室）

现场：实验室白天开灯，画面里是窗（过曝饱和）+ 暗墙/窗帘 + 桌上的仪器。
灰度直方图**非常双峰**（`mean=69.5 std=81.8`，15% 像素饱和在 255，同时大量像素在 0~30）。

UART 实时扫（`tools/live_sweep.ps1` + `tools/analyze_sweep.py`，`T=t16/t24/t32`、`S=0/1/2`、`E2 D3`）：

| 设置 | grey | dens% | comps | specks | frags | biggest |
|---|---|---|---|---|---|---|
| `S1 T16`（原默认） | 58.5 | 7.95 | 312 | 77 | 196 | 14633 |
| `S1 T16`（第二次） | 60.0 | 8.00 | 295 | 73 | 176 | 14592 |
| **`S0 T16`** | 57.1 | **1.82** | **85** | **20** | 48 | 2227 |
| `S2 T16` | 56.6 | 9.54 | 408 | 114 | 254 | 23032 |
| `S0 T24` | 61.6 | 1.83 | 101 | 32 | 53 | 2258 |
| `S0 T32` | 61.1 | 1.86 | 106 | 25 | 62 | 2660 |
| `S1 T16`（第三次） | 60.8 | 5.98 | 365 | 78 | 248 | 9368 |

> 漂移警告：同一设置的三次参照 `dens` 从 7.95→8.00→5.98，说明**这几分钟里场景变了**
> （白天窗光变化 / 有人动过），所以跨设置的绝对值只能做量级判断，不能抠小数点。

肉眼对比（`work/capture/sweep_edge_compare.png`）：

* `S1 T16`：暗墙上出现**密集竖线**（窗帘褶皱），仪器区域**大片连成白块**，脏。
* `S0 T16`：只剩**细而连续的轮廓**（墙缝 3 条干净竖线、仪器外形一圈），暗墙内部不再出噪点，
  最接近参照视频的观感。
* `S0 T24`：更稀疏，墙线仍在。

**结论：参照工程用的就是 `S0`（阈值 = 中心灰度本身），我们原默认 `S1` 等于把阈值砍半，
比参照敏感一倍，所以更脏。** `S0` + 我们已有的下限 `T` 就已经复现了参照的规则，
而且下限正好避免 §2.1 里"暗区整片变白"的退化。

运行时切 `S0` 不需要重新编译：`uart_send.ps1 -Commands S0,T16,D3,E2 -Port COM7`
（上板已验证回读 `THR=016 SH=0 DS=3 EN=2 SRC=U`）。

注：`flick%` 在这次扫描里从 18.2 跳到 49.4，同一设置两次参照就有 18.2→31.7 的漂移，
**这个场景下 `flick%` 不可信**，不能用来给 `S` 定档。
