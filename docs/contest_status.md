## "零延迟"口径（赛题原文）

赛题要求"摄像头采集一行的同时，FPGA 对该行数据进行处理并输出显示"。

- 行级流水线成立：灰度、中值、Sobel、阈值、去噪、外接框都是**逐像素流式**，
  没有任何整帧缓存参与运算路径，延迟是"几行 + 几十个像素时钟"。
- 但 DDR 帧缓存位于采集与显示之间（`frame_buffer_V4`），整帧写入再读出会引入
  **约一帧**的延迟。演示和答辩时说清这一点：算法链路是流水的、零帧缓存；
  DDR 是采集侧的帧缓冲。

## 演示屏与分辨率口径

- 板子 HDMI 固定输出 **1280x720@60**：`HACT=1280 / VACT=720`，总时序 1650x750，
  像素时钟 74.25 MHz，标准 CEA 720p60。链路内部 1:1，**不做任何缩放**。
  采集卡读到的也是 `1280x720 @ 60 fps`，`PIX=921600 = 1280*720`。
- 分屏方式（`rtl/edge_display_720p.v`）：左半 x=0..639 输出该位置灰度，
  x=640 是白色分隔列，右半 x=641..1279 输出该位置边缘。**两个半边各自显示
  自己那一半视野**，不是同一画面的"灰度 vs 边缘"对比。左右内容不一致是分屏
  方式决定的，换任何屏都一样。
- 最终演示屏是 **1280x800 的 HDMI 小屏**（2026-09-25 尚未到货）。到货后横向
  1280 与板子输出正好 1:1，纵向 720->800 由屏的驱动板拉伸或留黑边。
- 台面调试用的 Dell D2421H 是 1920x1080，会把 720p 拉满成 **1.5 倍**，
  所以屏上"图像显得很大"只是显示器行为，不是板子输出。判断像素级细节以
  采集卡 1:1 抓帧为准，不以屏幕观感为准。
- 待评估（不是现在做）：若想让 1280x800 上下也点对点，需要把输出时序改成
  1280x800@60（像素时钟 83.5 MHz）。当前最差 setup 裕量只有 +0.49 ns，提速前
  必须先做时序评估。

## 2026-09-25 更新：暗区轮廓（tone curve + 局部迟滞）

板子持有人反馈"屏幕现在有很多地方是黑的，轮廓没有显示出来"。按赛题"参考公开实现"的
思路去 GitHub 找了 FPGA 图像处理的工程，借到的是 DOUDIU 那套 Canny 的**局部**双阈值迟滞
（`out = 弱边 && 3x3 邻域内有强边`，见 `docs/reference_source_review.md` 第 7 节）。

组合方案（离线 2 帧验证，`docs/capture_and_quantify.md`）：

1. **tone curve**：64 以下 2 倍、之后压到 255（`rtl/tone_curve_lut.v`）——解决"8 bit 的暗部
   只用了 0~48"这个根因；
2. **局部迟滞**：固定 24/48，弱边只在贴到强边时保留（`rtl/edge_overlay_720p.v`）——把提亮
   一起放大的孤立噪声扔掉；
3. 自适应项在这一版里**关掉**（`S8`）：曲线已经把亮度归一化了，固定阈值反而更干净。

量化：暗区边缘密度 **7.15 % → 20.4 %**（2.9 倍）、碎斑 188 → 5、连通域中位面积 6 → 13 px、
长链(>=40px) 56 → 160 条、长链内像素占比 93 %。

上电默认 `T24 S8 D3 E2 C1 H1`；`C<n>` / `H<n>` 两个 UART 命令可以单独关掉曲线或迟滞做 A/B
（按键路径到不了这两个开关）。UART 状态行尾部新增 `CV=n HY=n`。

编译 PASS，最差 setup slack +0.286 ns（0 条 violated），资源 XLR 37.4 % / FF 8.6 % /
Memory 47.7 %。

**已 JTAG 烧录并回读确认**（2026-09-25，`tools/build/program.bat`，没碰 Flash）：
`THR=024 SH=8 DS=3 EN=2 SRC=U PIX=921600 CV=1 HY=1`，新默认全部生效。

板上交错 A/B 实测（细节见 `docs/capture_and_quantify.md`）：

* 逐像素翻转率（“闪”的正面指标）**8.4/6.0/4.1 % -> 1.6/1.3/1.7 %**，迟滞把时域抖动量
  压低 3~5 倍；
* 连通域中位面积 **4~5 px -> 10~19 px**（4/4 轮一致）；碎斑（<=3 px）134/145 -> 41/56；
* 观感从“整屏竖条纹理噪声”变成**干净线框**，与参照视频（`work/analysis/refvideo/`）同一种风格。

随后仍需：修外接框撑满屏、录演示视频、整理提交包、等 1280x800 屏到货。

## 2026-09-26 更新：floor 24 -> 16，以及离线能答 / 不能答的边界

板子持有人反馈"很多地方是黑的，轮廓没有显示出来"。离线链条在抓图的**左半**（就是送进
Sobel 的那张灰度）上复现板子行为，可信度已校验（`ab3_b1`：离线 15.9 % vs 板上 16.2 %）。

* **自适应项在暗区帮不上忙**：`active = max(local_mean >> shift, floor)` 只会抬高阈值，
  暗区恒等于 floor，而迟滞的强种子写死在 2×floor。白天台面 30 帧里灰度半幅 **64 % 低于
  48/255**，24/48 这一对只点亮其中 **7.4 %**，16/32 点亮 **16.7 %**——暗轮廓不是"太弱"，
  是**根本没到 48**。
* 只动 floor（24→16），shift 保持 8，保证上板 A/B 可归因；KEY1 一次 +8 就回到旧值。
  碎斑率不升（0.01 %），长链占比保持 92 %，说明多出来的是结构不是噪点。
* **NMS 离线否决**：像素压到 1/3，但连通域 431→1175、碎片 6→299（四方向量化在拐角处切
  断口），且 1 像素线会被 D3 去碎斑整体抹掉。补齐 Canny 第五步需要整链重调，不是插一个模块。
* **外接框本轮不改**：全 min/max 只在"角落孤立点"场景退化；投影法能把那种场景从 96 % 收到
  34 %（覆盖 75 %），但画面本身铺满边缘时任何规则都收不小。改它要 ~1140 个 FF 且当前无法
  上板验证，故留档不改。
* 墙上竖条纹经 `tools/box_probe.py --frame` 确认是**真实窗帘褶皱**，不是 2 像素梳状伪影
  （A_x +0.0016）。

编译 PASS，最差 setup slack **+0.279 ns**，0 violated；XLR 37.4 % / FF 8.6 % / Memory
122/256 / DSP 4/160。**位流未烧录**——板子的 USB（COM5..COM8）与 HDMI 采集卡当前都不在电脑上。

上板后第一件事（不重新编译即可做）：`T16 S8` → `T20 S8` → `T24 S8` 三档 A/B，用
`tools/live_sweep.ps1` 抓帧看**逐像素翻转率**有没有随 floor 下降而变差。细节见
`docs/tuning_findings.md` 第 6 节。
