# 3x3 去噪 + 目标外接框（`rtl/edge_overlay_720p.v`）

赛题高阶第 ⑥ 项「简易目标识别」，外加 ① 中值滤波之后的第二级去噪。
对应位流 `candidate_bitstreams/overlay_box.bit`（分支 `uart-bringup`）。

数据流：`median_filter_3x3_720p` → `edge_display_720p`（左半灰度 / 右半二值
Sobel）→ **`edge_overlay_720p`（本模块）** → `dvi_encoder`。

本模块把整条流**整体延迟 1 个像素时钟**（vs / hs / de 与 RGB 一起走），DVI
编码器对此不敏感。所有"输出侧"的判断都必须用 `s_x / s_y`（当前输出像素的坐
标），不能用 `x_now / y_now`（当前输入像素的坐标）——这两个差 1，是本模块最
容易写错的地方。

## 1. 去噪：为什么不能用教科书的 9 输入与

形态学腐蚀（3x3 全 1 才保留）在这里是**错的**：Sobel 边缘只有 1~2 像素宽，
一条 1 像素粗的直线（横线/竖线/斜线）在它自己的 3x3 窗口里**恰好只有 3 个
亮点**，9 输入与会把整幅边缘全部擦掉。

所以判据改成**邻域计数**：

```
保留中心像素  <=>  中心为 1  且  8 邻域中为 1 的个数 >= i_despeckle_min
```

| 图案 | 3x3 内亮点数 | min=2 | min=3（默认） | min=5 |
|---|---|---|---|---|
| 孤立噪点（1 像素） | 1 | 删除 | 删除 | 删除 |
| 2 像素噪点 | 2 | **保留** | 删除 | 删除 |
| 1 像素宽直线/斜线 | 3 | 保留 | **保留** | 删除 |
| 拐角 / 粗边缘 | 4~6 | 保留 | 保留 | 部分删除 |

`i_despeckle_min = 0` 时**整条滤波旁路**（`edge_clean = center`），这就是 A/B
对照的参考臂。

## 2. 3x3 窗口对齐（踩过的坑）

- 窗口中心取 **`b_d1`**，即"上一个时钟进入的像素"，它正好是**当前送到输出的
  那个像素**（因为输出是输入延迟 1 拍）。三条行抽头必须落在**同一列**上。
- 上一行用 `sr1`：位宽必须是 `IMAGE_WIDTH+2`，抽头取
  `[IMAGE_WIDTH+1] / [IMAGE_WIDTH] / [IMAGE_WIDTH-1]`。
  位宽只写 `IMAGE_WIDTH+1` 时拿不到最左边那一列，上一行会整体**错开一列**，
  窗口就不是真正的 3x3 了。
- 上上行用 `sr2`（`sr1` 级联再延迟一拍），抽头 `[W] / [W-1] / [W-2]`。
- 两个移位寄存器只在**有效像素**上移位（`in_de && x_now < IMAGE_WIDTH`），
  消隐期不动，所以行间不会失步。
- 前 2 行、前 2 列的窗口不完整，`window_ok` 直接把它判为无边缘。
- 右半最右一列（`s_x = 1279`）是在下一行的第一个时钟才被送出的，那时抽头已
  经无效，所以这一列被画成黑色。它在画面最右边，实际看不见。

综合后的资源占用（Efinity map 报告）：`edge_overlay_inst` 用了 327 个 SRL8
（= 2616 bit，正好是 2563 bit 的两个行存）+ 1344 个 FF，没有 BRAM。

## 3. 目标外接框

一帧内对去噪后的边缘像素取 `x_min / x_max / y_min / y_max`，在 `frame_start`
锁存，**画到下一帧**（画框用当前帧的框值，所以不需要额外帧缓存）。框是红色
`(FF,00,00)`、线宽 2 像素，画在右半（与边缘图同侧），优先级高于边缘/灰度。

**诚实说明（局限）**：min/max 覆盖的是"所有边缘像素"，只要背景有一点点纹
理，框就会撑满整屏。它只在**背景基本均匀**（暗室、单一目标）时有意义。如果
实测框总是满屏，正确解法是**行/列投影 + 相对阈值**（统计每行/每列边缘数，
取最大值的一定比例作为阈值），而不是改 min/max。

## 4. 按键控制（KEY3 一键两用）

只剩 3 个可用键（KEY0 与复位 `i_arstn` 同脚），所以 KEY3 做成短按/长按：

| 操作 | 动作 |
|---|---|
| KEY1 短按 | 梯度门限 +8 |
| KEY2 短按 | 梯度门限 -8 |
| KEY3 **短按（松开时 <1 s）** | 下一个自适应档位 `{8,3,2,1,0}` |
| KEY3 **按住 >=1 s** | 下一个去噪档位 `{3,5,0,2}` |

- 短按动作在**松开**时触发，且只有"没按长"才触发，所以长按不会顺带改档位。
- 长按动作在**按住 1 s 的瞬间**触发，手不用抬就能看到效果。
- 实现：`key_debounce` 新增 `o_level`（消抖后的电平），`threshold_ctrl` 用
  25 MHz 计 25 000 000 拍判长按。

## 5. UART 遥测格式变化

| 时机 | 报文 |
|---|---|
| 复位后第一条（仅一次） | `TI60 UART OK\r\n`（14 字节，与旧位流一致） |
| 之后每 500 ms，或任一按键动作 | `THR=nnn SH=n DS=k\r\n`（19 字节） |

`DS` 就是 `i_despeckle_min`，这样串口日志能记录"这张画面是用哪个去噪档位拍
的"。两条报文长度不同，`uart_telemetry` 的报文节拍器改成按报文长度收尾。

## 6. 上板证据（2026-09-24）

- 编译：`map / interface / pnr / pgm` 全 PASS，最差裕量 **+0.408 ns**（全正）。
  新增的只有同类告警（`threshold_ctrl` 的加减法位宽截断提示，与上一版相同）。
- 烧录：`Device ID read from JTAG: 0x10660A79`。
- 遥测：COM5 5 秒收 171 字节，报文为

      THR=024 SH=1 DS=3

  与设计一致（上电默认 floor 24 / shift 1 / 去噪档 3）。

**还没拿到**：画面观感（板子持有人未描述）。去噪和红框的实际视觉效果需要在
显示器上看一眼；采集卡到货后可以用录屏做 A/B 量化。

## 7. 怎么做 A/B

1. 板子上电默认 `DS=3`（去噪开）。
2. 按住 KEY3 约 1 秒 → `DS=5`（更狠）；再按一次 → `DS=0`（**旁路**，等于旧
   行为）；再按 → `DS=2`。串口会同步打印，所以画面对应的档位不会记错。
3. 需要"编译期对照"时，把 `ti60f225_oob_top.v` 里 `threshold_ctrl` 的
   `.DESPECKLE_INIT` 从 `2'd2` 改成 `2'd0` 重编即可。
